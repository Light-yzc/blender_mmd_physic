# Blender MMD Physic

面向 MMD 角色的 Blender 骨骼物理配置工具。集中管理头发、裙摆、飘带和胸部的物理分组、碰撞体、区间烘焙，以及 Blender 原生布料的批量烘焙顺序。

**当前版本：5.34。** Blender 中显示名称为「骨骼链阻尼追踪」，入口位于 **3D 视图 → N 面板 → 骨骼链**。

## 功能

| 功能 | 说明 |
| --- | --- |
| 骨骼分组 | 分别管理头发、裙摆、飘带、胸部等部位 |
| Wiggle 集成 | 配置骨骼摆动、质量、劲度、阻尼、拉伸和碰撞集合 |
| Ruri 集成 | 支持骨骼布料与胸部用的骨骼弹簧 |
| 碰撞体 | 配置胶囊、球、盒体、椭球及局部偏移，支持清理无效引用 |
| 区间烘焙 | Ruri / Wiggle 生成独立动画动作，保留原动作恢复记录 |
| 单组停用 | 「取消本组物理」只停用当前组的实时模拟 |
| 原生布料批量烘焙 | 自动识别传统 Cloth 和 Cloth Dynamics 几何节点布料，包含代理对象 |
| 依赖顺序 | 先烘焙上游骨架，再按碰撞与代理依赖逐层烘焙布料 |
| 旧版防穿 | 保留基于限制距离约束的旧版配置 |

## 环境与依赖

当前开发环境为 **Blender 5.2.2 LTS / Linux**。其他版本与系统尚未完整验证；插件元数据中保留的 Blender 3.0 最低版本不代表全部新功能支持 Blender 3.x。

按需要安装对应依赖，无须为未使用的模式安装全部插件。

| 使用场景 | 所需组件 |
| --- | --- |
| Ruri 物理 | [RuriClothPhysics](https://github.com/ShiyumeMeguri/RuriClothPhysics)，当前适配环境为 8.0.0 |
| Wiggle 物理 | [Wiggle 2: RTX Edition](https://github.com/mayalhc/blender-wiggle-2)，当前安装环境的扩展版本为 2.4.0 |
| 传统 Cloth 批量烘焙 | Blender 自带 Cloth，无需额外物理插件 |
| Cloth Dynamics 批量烘焙 | 工程中已有原生 Cloth Dynamics 几何节点布料修改器 |

本工具通过依赖插件的运行时接口调用模拟，普通版 Wiggle 或其他版本的 Ruri 不保证兼容。「启用 Ruri 前置」只启用已经安装的 Ruri，不负责下载。

本仓库提供本地适配时使用的两份兼容补丁，见 [补丁说明](patches/README.md)。第三方插件需要单独安装。

## 安装

1. 下载仓库中的 [自动物理.py](自动物理.py)。
2. 在 Blender 打开 **编辑 → 偏好设置 → 插件 → 从磁盘安装**，选择这个 `.py` 文件。
3. 启用「骨骼链阻尼追踪」。
4. 根据使用模式安装并启用 Ruri 或 Wiggle。
5. 返回 3D 视图，按 `N`，打开「骨骼链」标签。

Linux 隔离烘焙还需要工具文件：把仓库 `tools/bake_limited.py` 放到插件安装目录旁的 `bonechain_tools/bake_limited.py`。直接从仓库路径加载插件时，会自动使用仓库的 `tools` 目录。

更新时替换同名文件，并同时更新这个工具文件。保存工程并重启 Blender，使已加载的旧版代码完整卸载。

## 快速开始

### 头发、裙摆与飘带

1. 选中骨架，进入 **姿态模式**。
2. 新建分组，例如 `hair`。
3. 选中需要模拟的骨骼，点击柔性骨骼组的「添加选中」。
4. 在碰撞骨骼组中添加身体、手臂等固定支撑骨。
5. 选择 Wiggle 或 Ruri，再执行对应的配置按钮。
6. 从模拟起点连续播放，确认运动和碰撞后再烘焙。

Ruri 的默认骨骼布料模式会固定列表中每条链的第一根骨骼，让后续成员参与模拟。只有互为同级的两根骨骼不能按这个默认方式构成一条可动链。

### 胸部弹簧

1. 新建胸部分组，把左右胸部驱动骨放在同一组。
2. 选择 **Ruri → 骨骼弹簧（胸部）**。
3. 在碰撞骨骼列表添加身体、前臂和手掌等需要交互的骨骼。
4. 点击「配置 Ruri 骨骼布料」。这个按钮也负责应用弹簧类型。
5. 配置后在「本组弹簧参数」调整最大摆幅、回位力、混合量和惯性。

弹簧类型让所选骨骼在动画原位附近运动，不需要手动新建父骨。

**骨骼名称不能代替实际驱动关系。** 某些 MMD 模型的辅助控制骨只把少部分位移传给变形骨。本次排查的模型中，`胸上2.L/R` 的位移经过约束后只传递 0.1 倍；换用 `胸00.L/R` 才能更直接地带动表面。这是该模型的具体关系，不是所有模型通用的骨骼命名规则。

该模型直接驱动的参考起点：

| 参数 | 参考值 |
| --- | --- |
| 最大摆幅 | 0.01 米 |
| 回位力 | 0.04 |
| 模拟混合量 | 0.7 |
| 世界惯性 / 局部惯性 | 各 0.75 |
| 世界惯性平滑 | 0.4，在 Ruri 原生惯性面板调整 |

这些数值不是通用预设。插件首次切入弹簧类型时使用另一组较保守的默认值，已有参数不会在每次重新配置时被覆盖。

## 手部碰撞

- 把手掌骨加入**胸部分组的碰撞骨骼列表**，不是柔性骨骼列表。
- 只有上臂、前臂碰撞体，不能完整覆盖手掌。常见 MMD 手掌骨名称为 `手首.L/R`，以实际模型为准。
- 调整碰撞体的尺寸和偏移，使它包住手掌，再重新配置。
- Ruri 弹簧类型使用逐点碰撞，检测的是骨骼粒子，不是胸部整个网格表面；可见皮肤接触不一定等于粒子已经接触。
- 最大摆幅会限制碰撞推开的距离，不能据此保证完全防穿。

## 区间烘焙、删除与单组停用

| 操作 | 作用范围与结果 |
| --- | --- |
| Ruri「区间烘焙」 | 当前骨架中全部启用的 Ruri 配置，写入独立动作 |
| Ruri「Delete Bake」 | 按骨架记录恢复原动作，并删除可安全删除的本轮烘焙动作 |
| Ruri「恢复实时」 | 按骨架恢复原动作与实时模拟，保留烘焙动作 |
| Wiggle「区间烘焙」 | 按当前骨架的可用 Wiggle 骨骼烘焙 |
| Wiggle「取消烘焙」 | 按骨架记录恢复烘焙前动作，保留烘焙动作 |
| 「取消本组物理」 | 仅停用当前组实时 Ruri / Wiggle / 旧碰撞，恢复已记录的 MMD 跟随 |

**单组停用不会移除已经写入动画动作的物理关键帧。** 它不切换整副骨架的动作，也不会要求先取消其他组的烘焙。已有关键帧仍会播放。

只有当前插件记录过的烘焙才能自动恢复。旧版覆盖写入、缺失备份的动作不能凭空还原。列表里的「移除」或「清空」也不能代替停用已经应用的物理。

## 一键烘焙 Blender 原生布料

入口：**骨骼链 → 场景原生布料烘焙**。这个区域在物体模式和姿态模式均可使用，默认折叠，点击标题展开。

1. 设置起止帧，或点「使用场景区间」。
2. 设置预模拟帧数，默认 30 帧。
3. 保持「先烘焙上游 Ruri／Wiggle」开启。
4. 选择「正常烘焙」或「内存受限烘焙」。正常烘焙在当前 Blender 执行；内存受限烘焙仅支持 Linux 节点布料，需要保存工程后运行，结果另存新副本。
5. 正常烘焙完成后保存 `.blend`；内存受限烘焙完成后打开日志中记录的新副本。两种路径都需保留工程旁的缓存目录。节点布料明确写入磁盘；传统 Cloth 使用磁盘点缓存。

例如：动画 600–700 帧、预模拟 30 帧，会把骨骼和布料的烘焙计算区间设为 570–700 帧，场景动画区间保持原样。

执行顺序：

```text
布料依赖的骨架物理（例如胸部、头发）
    ↓
作为碰撞体或代理的上游布料
    ↓
依赖上游结果的衣物、裙摆与饰品
```

批处理以**场景**为范围，上游骨骼按**骨架**烘焙启用配置，不是只烘焙当前胸部分组。被手动停用的 Cloth 修改器会跳过；隐藏代理会临时显示用于烘焙，结束后恢复隐藏和选择状态。

同一依赖层中的节点布料逐对象烘焙。采样骨骼时暂停下游布料，烘焙布料时暂时暂停尚未轮到的下游对象，结束或中止后恢复修改器显示状态，以减少无用的实时模拟缓存。

按 `Esc` 中止。已经完成的阶段保留，具体顺序与结果写入工程内的文本 **「原生布料烘焙记录」**。

「删除场景布料烘焙」只删除启用布料对象的原生缓存，保留 Ruri / Wiggle 骨骼烘焙动作。

### Bake 时的内存保护

Blender 5.2 的原生节点 Bake 会保留已经计算的帧状态，**写磁盘也不等于逐帧释放内存**。5.32 的存储改动不足以限制单个长 Bake 的内存。

5.34 将两条路径分为独立按钮：「正常烘焙」在当前进程执行，没有内存硬上限；「内存受限烘焙」使用独立进程：先处理上游骨架，再按依赖顺序每个对象启动一次 Blender。一个对象在完整区间内连续模拟，完成后保存进度并退出进程，再处理下一个对象。不会把时间区间截断为独立模拟。

默认工作进程上限 8 GiB；每次启动前还会将它下调至「当前可用物理内存减 1.5 GiB」以内，且禁用该工作单元的交换空间。单个任务超过上限会被终止，队列停止；这保证有上限，不保证任意复杂对象都能在上限内完成。主界面原有内存不会因此被清理；建议使用已经导出磁盘缓存的工程副本。

内存受限模式没有降低求解质量、子步、网格精度或跳过帧；每个对象仍连续模拟整个区间。额外的进程启动和工程读写可能降低整体速度。尚未做两条路径的结果对比，不能承诺逐位一致；超限会停止，而不会自动降质量继续。

需要先保存工程与设置。烘焙结果写入同目录 `原名-limited-bake-随机标识.blend` 和它的缓存目录，原工程、原磁盘缓存保留。`Esc` 请求中止；日志显示停止位置。中止或超限后，失败阶段的缓存可能不完整，工具不会自动继续。

也可从命令行运行：

```bash
python3 tools/bake_limited.py /path/to/project.blend --blender /path/to/blender --memory-limit 8G
```

默认使用插件里保存的区间与预模拟设置。此隔离工具目前只处理可识别的**几何节点布料**，遇到传统 Cloth 会明确停止；「正常烘焙」支持原有传统 Cloth 路径，但没有内存硬上限。隔离 Bake 完整流程尚未实测。

### 长序列与内存

5.32 起使用磁盘缓存，避免把整段节点模拟打包进 `.blend`。**这不等于 Blender 播放时只保留一帧内存**：5.2 的节点模拟会保留已加载的帧状态，长序列仍可能增加内存占用。旧工程中的打包缓存也不会因为更新插件自动转为磁盘缓存。

仓库提供 Linux 分段渲染工具，每段使用独立 Blender 进程，并以用户 systemd 限制工作进程的内存，默认 8 GB、不使用交换空间。默认每 32 帧退出进程，释放该段累计的节点与渲染缓存。超限只会终止该工作单元，队列随即停止，不自动重试。

先保存好物理烘焙和图像序列输出设置，然后运行：

```bash
python3 tools/render_chunks.py /path/to/project.blend \
  --blender /path/to/blender \
  --start 600 --end 3240 --chunk-size 32 --memory-limit 8G
```

工具沿用工程内的渲染器、相机、分辨率和输出位置，不改写工程。需要 PNG / EXR / JPEG 等图像序列，不能直接分段输出视频；已有同名输出可能被覆盖。物理应事先烘焙，工具不补算或修改缓存区间。根据机器可用内存调整上限；单帧本身就超过上限时，需要降低渲染开销或增大上限。普通界面的「渲染动画」不会自动变成分段渲染，也没有这个进程内存上限。

内存改动已做代码检查；磁盘缓存转换与工程重新打开完成过实际诊断。新的批处理与分段渲染尚未运行完整长序列，不能保证已消除所有渲染崩溃。

### 依赖循环

碰撞与变形不能形成循环。例如：

```text
上层裙摆 Proxy → 碰撞集合 → 上层裙摆网格 → Surface Deform → 同一个 Proxy
```

批处理会在执行前报出循环对象，先修正碰撞集合再重新执行。可采用单向关系：身体驱动上层裙摆，上层裙摆再作为下层裙摆的碰撞来源。

## 常见问题

### 饰品没有跟着胸部动

先检查实际权重与骨骼约束，再检查饰品是否保存着胸部修改前的 Cloth 缓存。旧缓存可能覆盖新的骨骼形变。

- 只需要贴身跟随的饰品：保留 Armature，停用它自己的 Cloth 修改器。
- 还需要独立布料运动的饰品：先完成胸部骨骼烘焙，再删除饰品旧缓存并重新烘焙 Cloth。

### 不烘焙时偶尔没有物理

模拟依赖历史帧。不要只跳到某一帧判断效果；回到起点连续播放，或用原生「Calculate to Frame」完整计算。

### 胸部变形太大或几乎不动

检查是否选了正确的直接驱动骨、是否使用弹簧类型，以及原模型的 MMD 约束是否缩小或重复传递了位移。然后调整最大摆幅、混合量和惯性。

### Ruri 首次播放卡顿

首次使用可能需要编译求解内核。编译目标、依赖安装与设备支持由 Ruri 管理。

## 当前验证状态与限制

- 开发过程中在 Blender 5.2.2 上对具体工程做过实时运动、骨骼驱动和原生缓存的数值排查。
- **5.30 新增的整段批量烘焙流程仅完成语法和静态检查，尚未完成完整流程实测。**
- 节点布料通过带缓存的修改器/节点组名称中的 `cloth` 或「布料」识别；任意重命名的自定义模拟不保证被识别。
- 当前视图层排除的布料集合需要先启用。
- 同一个对象混合传统 Cloth 与节点布料、或混合其他节点模拟时，会要求拆分模拟对象，避免对象级 Bake 波及其他模拟。
- 同一骨架同时实时运行 Ruri 与 Wiggle 时，会要求先分别完成骨骼烘焙，避免互相覆盖动作。
- 批处理支持这里列出的骨骼物理与布料依赖，不是 Blender 全部物理系统的通用烘焙管理器。
